# Шпаргалка к защите ЛР1

## 1. Что сказать про проект
«Это минимальная информационная система рыболовной фирмы. Она хранит катера, команды, рейсы, сорта рыбы и улов. Рейс связывает катер и команду, а улов относится к рейсу и сорту рыбы.»

## 2. Как показать запуск
```bash
cp .env.example .env
make up
make container-check
```
Потом открыть `http://localhost:8000/docs`.

## 3. Как показать БД
```bash
docker compose exec db psql -U fishing -d fishing
```
В psql:
```sql
\dt
SELECT * FROM boats;
SELECT * FROM trips;
SELECT * FROM catches;
```
Выйти: `\q`.

## 4. Как объяснить Git
Показать:
```bash
git log --oneline --graph --decorate --all
git branch -a
git tag
```
Рассказать цепочку:
задача → feature-ветка → несколько коммитов → push → PR/MR → review → merge → tag v0.1.0.

## 5. Контрольное изменение
Создать маленькое изменение, например дополнительное поле в README или сообщение health-check, сделать отдельную ветку, минимум два осмысленных коммита, `make verify`, push, PR/MR, merge.

## 6. Конфликт
Намеренно изменить одну и ту же строку README в двух ветках и выполнить `git merge`. Показать конфликт, маркеры, исправление, `git add`, `git commit`.

## 7. Главный вопрос преподавателя: «Какое бизнес-правило?»
Ответ: «Для каждого рейса суммарный вес улова не должен превышать грузоподъёмность выбранного катера. Перед добавлением нового улова приложение суммирует уже записанный улов и сравнивает его с capacity_kg. При превышении возвращается HTTP 422.»

## 8. Ошибки
- 422 - невалидные входные данные / нарушение предметного правила.
- 404 - отсутствует связанный катер, команда, рейс или сорт рыбы.
- 409 - попытка создать дубликат уникального справочника.

## 9. Почему .env.example есть, а .env нет
`.env.example` показывает, какие переменные нужны, но не содержит реального секрета. `.env` добавлен в `.gitignore`, поэтому локальный пароль не должен попасть в репозиторий.

Затем показать Swagger, таблицы БД и PR/MR.

### Health-check

Для демонстрации работоспособности API используется служебный endpoint:

```text
GET /health
```
Ожидаемый HTTP-код: 200.

Пример проверки:

```bash
curl http://localhost:8000/health
```
